## 3. Defects demonstrated on the pre-M01 engine (`0693115`)

The old `cpm.py` was loaded directly from git and exercised:

```
chain 1200: accepted
bool duration accepted as: True True
duplicate dependency accepted: ['A', 'A']
non-mapping task body raised: TypeError - argument of type 'int' is not iterable
reversed chain 1200: RecursionError: maximum recursion depth exceeded
reversed chain 2000: RecursionError: maximum recursion depth exceeded
```

(The 1200-task chain inserted in ascending order happens to recurse only two
levels deep; the same chain inserted deepest-first exceeds the default
recursion limit. Both insertion orders are now tested.)

## 7. README / CV claim affected

The README claim "CPM engine … with dependency validation and cycle detection"
is now accurate in a stronger sense: validation is exhaustive and cycles are
detected without recursion. The README was also corrected to install
`.[dev,langgraph]` (installing `.[dev]` alone leaves coverage at ~74% and fails
the 80% gate). The `critical_path` field is now documented as a sorted set of
zero-slack task ids rather than an ordered walk.

## 8. Remaining limitations

See `docs/M01.md`. Summary: integer durations only; `critical_path` is a set;
no resources/calendars/lags; the defensive post-Kahn guard is untested by
design; large-graph checks are correctness, not performance, benchmarks.
