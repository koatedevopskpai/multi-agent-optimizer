## What it is

A deterministic-first project-scheduling optimiser. A **Critical Path Method engine**
computes the schedule; three LLM agents — **Scheduler, Risk, Optimiser** — add
commentary, risk synthesis and suggestions under one `Orchestrator`.

The ordering matters and is the design: **the schedule is computed before any
provider is consulted**. A timeout, a rate limit, malformed JSON or a repeated
failure can therefore only remove the optional LLM notes — never a scheduling fact.

## How to reproduce

**Offline, free, no provider key** — this is what CI runs:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev,langgraph]"    # langgraph is required for the coverage gate
python -m pytest                     # 115 tests, >=80% coverage enforced
python evals/evaluate.py             # 11 golden cases
python -m multi_agent_optimizer.main # worked example
```

`langgraph` is **not** optional for a green local run: installing only `.[dev]`
leaves `lg_graph.py` and part of `agents.py` unimported, so coverage falls below the
gate. CI installs `.[dev,langgraph]` for the same reason.

`evals/EVAL_REPORT.md` is generated by the gate and **gitignored** — it is a run
artifact, not a committed result. The durable statement is the committed golden cases
and the code that checks them.

**Live, billable, not part of this evidence.** Setting `LLM_PROVIDER` and
`LLM_API_KEY` enables model enrichment. **No provider call was made for this index**;
every figure above is offline, and the failure paths were exercised with local fakes.

## One success trace, one failure

**Success.** The worked example computes a 17-day project with critical path
`A, B, D, F`, flags those four `HIGH` risk, and proposes a resource move per critical
task — all before any provider is consulted:

```text
$ python -m multi_agent_optimizer.main
Project duration : 17 days
Critical path    : A, B, D, F

Schedule:
A  es=0  ef=3  slack=0  CRITICAL
C  es=3  ef=7  slack=6
E  es=7  ef=8  slack=6
B  es=3  ef=5  slack=0  CRITICAL
D  es=5  ef=14 slack=0  CRITICAL
F  es=14 ef=17 slack=0  CRITICAL

Risks:
  [HIGH] A, B, D, F — on the critical path: any delay extends the project
```

(Abridged only where the suggestion lines repeat the same shape per task.)

**Failure, blocked by design.** Malformed projects do not produce a schedule. Cycles,
unknown or duplicate dependencies, negative or non-integer durations and mistyped task
bodies raise `ProjectError`. Rejecting the input is the correct outcome; a guessed
schedule would be worse than none.

**Failure that cannot change the schedule.** Each agent call is retried once, then
counted by a per-agent circuit breaker (3 consecutive failures opens it for 30
seconds, during which no provider call is made). Invalid JSON, wrong schemas,
timeouts, HTTP 429 and connection failures all take the same documented fallback:
Scheduler → the deterministic schedule table; Risk → no `llm-note`, CPM risks
unchanged; Optimiser → no `llm-note`, CPM suggestions unchanged. The full matrix,
including core-vs-LangGraph, is in [`docs/M02.md`](docs/M02.md).

## What this does not establish

- **Fractional or calendar time.** `duration` is an integer in an unspecified unit.
  Fractional durations are not supported.
- **Anything beyond finish-to-start with zero lag.** No resources, calendars,
  leads/lags, PERT estimates or maximum durations.
- **An ordered critical path.** `critical_path` is the sorted set of zero-slack task
  ids, not a walk. With several critical paths, every task on any of them appears.
- **LLM answer quality.** Enrichment is optional, ran against local fakes here, and
  is unverified against a real provider.
- **Production anything.** No customer, deployment, uptime or multi-tenant claim.
  Figures are one Windows host on 18 October 2026 plus CI on Linux.

## Known weaknesses

- `main.py` is at **0% coverage** — it is the demo entry point, not library logic.
  The 80% floor is met at the total, not per file.
- The eval gate is **11 cases**: a regression check, not a scheduling benchmark.
- The circuit breaker is **in-process**. It does not coordinate across workers.
- Durations are unit-less by design, which means `17` is meaningful only relative to
  the input; nothing here validates that an estimate is *right*.
